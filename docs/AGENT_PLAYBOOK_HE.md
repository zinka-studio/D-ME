# מדריך הקמה לסוכן: צעד אחרי צעד

המדריך משלים את `AGENTS.md`. הכללים שם מחייבים בכל שלב: עברית פשוטה, צעד אחד בכל פעם, שום סוד לא עובר בצ'אט, וההתחברויות והתשלומים בידי המשתמש.

בכל שלב יש: **מטרה**, **מה עושים**, **איך יודעים שהצליח**, ו**אם נתקע**.

## שלב 0: היכרות ובדיקת דרישות

**מטרה:** לוודא שאפשר להתחיל.

**מה עושים:**
1. מסבירים במשפט אחד מה ייבנה בסוף: דשבורד אישי באינטרנט, שמגיב אוטומטית בהודעה פרטית למי שמגיב על פוסט, ריל או סטורי שלו.
2. שואלים: איזו מערכת הפעלה (Windows, Mac), ואיך ייקרא חשבון האינסטגרם.
3. בודקים בטרמינל: `node -v` (נדרש 20 ומעלה) ו-`git --version`. אם חסר Node.js, מנחים להתקין את גרסת ה-LTS מ-`https://nodejs.org` ולפתוח טרמינל חדש.
4. מריצים `npm install` בתיקיית הריפו.
5. מוודאים שחשבון האינסטגרם הוא **מקצועי** (עסקי או יוצר). אם לא: באפליקציית אינסטגרם, הגדרות, "סוג חשבון ועבודה", מעבר לחשבון מקצועי.

**איך יודעים שהצליח:** `npm test` עובר ללא שגיאות.

## שלב 1: חשבון Cloudflare

**מטרה:** חשבון שבו ירוץ הדשבורד. המסלול החינמי מספיק להתחלה, בלי כרטיס אשראי.

**מה עושים:**
1. המשתמש פותח `https://dash.cloudflare.com/sign-up` (אפשר לפתוח בדפדפן בשבילו אם יש כלי דפדפן), נרשם עם אימייל וסיסמה בעצמו, ומאשר את האימייל.
2. בלוח של Cloudflare, בתפריט הצד, נכנסים ל-Workers & Pages. בפעם הראשונה יתבקש לבחור **כתובת משנה** (`<שם>.workers.dev`). זו הכתובת שבה יישב הדשבורד. מסבירים שהשם גלוי ושאפשר לבחור שם ניטרלי.

**איך יודעים שהצליח:** המשתמש רואה את הלוח של Workers & Pages בלי הודעות חסימה.

**אם נתקע:** אין מייל אימות (לבדוק ספאם), או שהחשבון מבקש אימות נוסף. זה בידי המשתמש.

## שלב 2: התחברות של הכלי ל-Cloudflare

**מטרה:** לאפשר לכלי `wrangler` לפעול בחשבון, בלי שהסיסמה עוברת דרכך.

**מה עושים:**
1. המשתמש מריץ בטרמינל שלו: `npx wrangler login`. נפתח דפדפן, והוא לוחץ Allow.
2. אחר כך: `npx wrangler whoami`. מציג את שם החשבון והאימייל.

**איך יודעים שהצליח:** `whoami` מציג את החשבון הנכון. מבקשים מהמשתמש לאשר ש"זה החשבון שלי". אם יש כמה חשבונות, מוודאים שזה הנכון.

## שלב 3: חשבון מפתחים ואפליקציה ב-Meta

**מטרה:** אפליקציה שמאשרת ל-D-ME לקרוא תגובות ולשלוח הודעות מהחשבון המקצועי.

**מה עושים:**
1. המשתמש נכנס ל-`https://developers.facebook.com`, מתחבר (נדרש חשבון פייסבוק) ועובר הרשמה כמפתח, כולל אימות טלפון או אימייל.
2. **Create App.** שם האפליקציה: לא להשתמש בשם שמכיל "Insta", "IG" או "gram", כי Meta חוסמת שמות כאלה. לבחור שם משלו. אימייל קשר: שלו.
3. בבחירת סוג השימוש, לבחור באפשרות הקרובה ל-**Other** או **Business**, ואז להוסיף את המוצר **Instagram** ובו **API setup with Instagram login** (השם עשוי להשתנות).
4. במסך ה-API setup: **Add account** (הוספת החשבון המקצועי). יתחברו עם אינסטגרם ויאשרו. נוצר **Instagram account ID** מספרי. לרשום אותו, זה לא סוד.
5. **Generate token** לחשבון. זה הטוקן שבו תשתמש המערכת (תוקף ארוך, כ-60 יום). **לא מעתיקים אותו לצ'אט.** המשתמש שומר אותו בצד כדי להקליד אותו בשלב 4 בלבד.
6. באותו מסך מוצאים את **Instagram app secret** (להציג ולהעתיק לצד). גם הוא לא עובר בצ'אט.
7. ההרשאות שנדרשות: `instagram_business_basic`, `instagram_business_manage_comments`, `instagram_business_manage_messages`. אם נבקשות במסך ההוספה, מאשרים את כולן.

**איך יודעים שהצליח:** המשתמש יודע את ה-Instagram account ID, ושמור אצלו הטוקן וה-app secret.

**אם נתקע:** האפשרות "API setup with Instagram login" לא מופיעה: מחפשים בלוח בתפריט Products. Meta משנה את המסכים לעיתים. מתאימים את ההדרכה למה שרואים.

## שלב 4: ההתקנה (D1, secrets, פריסה)

**מטרה:** ליצור את מסד הנתונים, לשמור את הסודות בענן ולפרוס את הדשבורד.

**מה עושים:**
1. הסוכן מכין: מסביר מה יקרה. המשתמש מריץ **בטרמינל שלו** (לא דרך הסוכן):
   ```bash
   npm run setup -- --apply --instagram-user-id <ה-Instagram account ID>
   ```
   אפשר גם בלי ה-ID בפקודה, והסקריפט ישאל.
2. הסקריפט מציג את חשבון ה-Cloudflare ומבקש לאשר. אחרי אישור הוא מריץ בדיקות, יוצר D1, מפעיל את המיגרציות, ומבקש בהזנה מוסתרת את **הטוקן של אינסטגרם** ואת **ה-app secret**. את אלה המשתמש מקליד או מדביק, ואין הד למסך.
3. הסקריפט מייצר בעצמו שני ערכים: **סיסמת ניהול** ו-**Verify token** לחיבור ה-webhook. הם נשמרים ב-`d-me-tokens.txt` ולא מודפסים.
4. בסוף מוצגות שתי כתובות: הדשבורד `/admin`, וכתובת ה-webhook `/webhook/instagram`. הסוכן יכול לקרוא את הכתובות (הן ב-`.d-me-install.json`), אבל לא את `d-me-tokens.txt`.
5. המשתמש פותח בעצמו את `d-me-tokens.txt`, מעתיק את שני הערכים למנהל סיסמאות, ומוחק את הקובץ.

**איך יודעים שהצליח:** `<כתובת>/health` מחזיר `{"ok":true}`. הסקריפט בודק זאת בעצמו.

**אם נתקע:**
- "wrangler לא מחובר": לחזור לשלב 2.
- אין כתובת workers.dev: לחזור לשלב 1, בחירת כתובת משנה.
- D1 נוצר והפריסה נכשלה: לא להריץ שוב מההתחלה. בודקים בלוח של Cloudflare, תחת Storage & Databases, D1, אם נוצר מסד בשם `<שם>-db`. פורסים שוב עם `npm run deploy` אחרי שמוודאים ש-`wrangler.local.jsonc` קיים.

## שלב 5: חיבור ה-webhook ב-Meta

**מטרה:** שאינסטגרם תשלח ל-D-ME כל תגובה והודעה חדשה.

**מה עושים:**
1. באפליקציה ב-Meta, באותו מסך ה-API setup, בחלק **Configure webhooks**.
2. **Callback URL:** כתובת ה-webhook משלב 4. **Verify token:** הערך שב-`d-me-tokens.txt` (המשתמש מדביק בעצמו). לוחצים **Verify and save**.
3. מסמנים את האירועים (fields) **comments** ו-**messages**, ומאפשרים את המנוי לחשבון (Subscribe).

**איך יודעים שהצליח:** Meta מאשרת את ה-Callback בלי שגיאה.

**אם נתקע:**
- Meta לא מאשרת: ה-Verify token שונה ממה שנשמר, או שהכתובת לא נכונה. בודקים מול `d-me-tokens.txt`.
- בהמשך, אם אירועים מגיעים ומקבלים 401: ה-app secret שהוזן אינו זה ש-Meta משתמשת בו לחתימה. מנסים את ה-**App secret** של האפליקציה (App settings, Basic) והחלפה: `npx wrangler secret put IG_APP_SECRET --config wrangler.local.jsonc`.

## שלב 6: הדשבורד והאוטומציה הראשונה

**מה עושים:**
1. פותחים את `<כתובת>/admin`. בשדה "מפתח ניהול" מזינים את סיסמת הניהול, ולוחצים חיבור.
2. בוחרים תוכן: **פוסט**, **ריל** או **סטורי**. אפשר לבחור כמה, או "כל הפוסטים".
3. כותבים מילות תגובה (למשל "לינק"), את הלינק והודעה פרטית, ובוחרים אם לשלוח רק לעוקבים.
4. שומרים. בצד מופיעות "רצות עכשיו", וקוביות הסיכום מציגות את הספירות.

**איך יודעים שהצליח:** האוטומציה מופיעה ברשימה כפעילה, והפוסטים נטענו מהאינסטגרם של המשתמש.

## שלב 7: בדיקת קבלה אמיתית

**חשוב:** כל עוד האפליקציה ב-Meta במצב **Development**, אירועים מגיעים רק מחשבונות שיש להם תפקיד באפליקציה (App roles: מנהל, מפתח, בודק). לכן בודקים קודם מחשבון בודק: ב-Meta, App roles, מוסיפים חשבון אינסטגרם שני כ-**Instagram Tester**, והוא מאשר את ההזמנה בהגדרות האינסטגרם שלו.

**מה עושים:**
1. מהחשבון הבודק מגיבים על הפוסט במילת הטריגר.
2. בודקים: ההודעה הפרטית מגיעה פעם אחת בלבד. אם הוגדרה בדיקת עוקב, חשבון שלא עוקב מקבל בקשה עם כפתור, ורק אחרי שעקב ולחץ מקבל את הלינק.
3. בודקים תגובה לסטורי, אם הוגדרה אוטומציה לסטורי.
4. לוגים: בלוח של Cloudflare, Workers & Pages, הוא ה-Worker, Observability, רואים את האירועים שנקלטו.

**כדי שגולשים אחרים (לא בודקים) יפעילו את האוטומציה:** האפליקציה צריכה להיות במצב **Live**, וייתכן שנדרש **App Review** להרשאות ההודעות וה-comments (Advanced access), כולל כתובת מדיניות פרטיות. הדרישות של Meta משתנות. מנחים את המשתמש לבדוק בתיעוד הרשמי בזמן ההקמה, ולא מבטיחים מראש שזה יעבור. אומרים לו בפשטות מה עובד כבר עכשיו ומה תלוי באישור של Meta.

**ההקמה נחשבת גמורה** רק כשבדיקה מחשבון בודק עברה.

## שלב 8: תחזוקה

- **חידוש הטוקן:** הטוקן של אינסטגרם פג אחרי כ-60 יום. כשבועיים לפני כן מרעננים אותו, מקליד בעצמו (לא בצ'אט):
  `https://graph.instagram.com/refresh_access_token?grant_type=ig_refresh_token&access_token=<הטוקן הנוכחי>` מחזיר טוקן חדש. אחר כך `npx wrangler secret put IG_ACCESS_TOKEN --config wrangler.local.jsonc`. מוסיפים תזכורת ביומן.
- **החלפת סיסמת ניהול:** `npx wrangler secret put ADMIN_TOKEN --config wrangler.local.jsonc`. הסיסמה הישנה מפסיקה לעבוד מיד.
- **עדכון גרסה:** `git pull`, `npm test`, `npm run deploy`.
- **עלויות:** Workers ו-D1 במסלול החינמי מספיקים לרוב העסקים הקטנים. בודקים את המגבלות העדכניות בלוח של Cloudflare.
