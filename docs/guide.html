הדרך הקלה: סוכן AI מוביל

פותחים את תיקיית הריפו ב-Claude Code או ב-Codex, ואם אפשר מחברים גם Claude בכרום. כותבים לסוכן:

קרא את AGENTS.md והדרך אותי צעד אחר צעד להתקנה של D-ME, מהרגע שאין לי שום חשבון ועד שהדשבורד רץ.

הסוכן מוביל בעברית. סיסמאות, קודי אימות, תשלומים וטוקנים מקלידים בעצמך, ולא בצ'אט.

המדריך שלמטה מתאר את אותם שלבים, אם מעדיפים ללכת בלי סוכן או לראות מה הולך לקרות.

בדיקת דרישות

  • חשבון אינסטגרם מקצועי (עסקי או יוצר). אם הוא אישי: באפליקציה, הגדרות, "סוג חשבון ועבודה", מעבר לחשבון מקצועי.
  • חשבון פייסבוק, לצורך חשבון מפתחים ב-Meta.
  • Node.js 20 ומעלה (גרסת LTS מ-nodejs.org) ו-git.
node -v
git --version
npm ci
npm test
איך יודעים שהצליח: npm test עובר בלי שגיאות.
1

חשבון Cloudflare

החשבון שבו ירוץ הדשבורד. המסלול החינמי מספיק להתחלה, בלי כרטיס אשראי.

  1. נכנסים ל-dash.cloudflare.com/sign-up ונרשמים עם אימייל וסיסמה.
  2. מאשרים את האימייל.
  3. בתפריט הצד נכנסים ל-Workers & Pages. בפעם הראשונה בוחרים כתובת משנה (<שם>.workers.dev). השם גלוי, ולכן כדאי שם ניטרלי.
איך יודעים שהצליח: רואים את הלוח של Workers & Pages בלי הודעות חסימה.
2

התחברות של הכלי ל-Cloudflare

ככה הכלי wrangler יכול לפעול בחשבון בלי שהסיסמה עוברת דרך אף אחד. נפתח דפדפן, ולוחצים Allow.

npx wrangler login
npx wrangler whoami
איך יודעים שהצליח: whoami מציג את החשבון והאימייל שלך. אם יש כמה חשבונות, מוודאים שזה הנכון.
3

חשבון מפתחים ואפליקציה ב-Meta

האפליקציה היא מה שמאשר ל-D-ME לקרוא תגובות ולשלוח הודעות מהחשבון שלך.

שינוי של Meta (נובמבר 2026): אפליקציות חדשות לא מקבלות "Instagram login" אלא Unified Login: כתובת graph.facebook.com, הרשאות instagram_basic, instagram_manage_messages, instagram_manage_comments, וטוקן של Business Portfolio. אפליקציה ישנה שכבר קיימת ממשיכה לעבוד. ההתקנה בשלב 4 מוצאת בעצמה את הכתובת ואת מזהה החשבון.
  1. נכנסים ל-developers.facebook.com, מתחברים, ועוברים הרשמה כמפתח (כולל אימות).
  2. Create App עם ה-use case Manage messaging & content on Instagram. שם האפליקציה: בלי "Insta", "IG" או "gram". האפליקציה חייבת להיות בבעלות Business Portfolio (אפשר ליצור אחד בחינם). לעיתים מופיעה פעם אחת "Verification Required", ובניסיון נוסף זה מצליח.
  3. בלוח האפליקציה: Use cases > Manage messaging & content on Instagram > Customize > API setup with Unified login.
  4. Configure your app: Create new configuration. ב-Edit permissions משאירים רק instagram_basic, instagram_manage_messages, instagram_manage_comments, ואז Use this configuration. ב-Redirect URL מזינים כתובת HTTPS כלשהי ושומרים (D-ME לא משתמש בה). רושמים את סוג הטוקן ותוקפו מהתצוגה המקדימה.
  5. Generate access tokens: Add account, ומזמינים את חשבון האינסטגרם כ-Instagram Tester. מאשרים את ההזמנה באינסטגרם באתר: Settings > Website permissions > Apps and websites > Tester Invites. אחר כך Generate token, ומעתיקים את הטוקן: הוא מוצג פעם אחת בלבד. שומרים בצד. לא מדביקים בצ'אט.
  6. את ה-App secret מוצאים ב-App settings > Basic. משתמשים ב-ID וב-secret של אפליקציית Meta, ולא של Instagram. שומרים בצד.
איך יודעים שהצליח: יש טוקן ו-app secret שמורים בצד, ורשום תוקף הטוקן. מזהה החשבון לא נדרש: ההתקנה מוצאת אותו.

הלשונית "API setup with Unified login" לא מופיעה? האפליקציה לא בבעלות Business Portfolio. ה-Tester לא מופיע בטבלה? ההזמנה לא אושרה באינסטגרם באתר. חשבונות בדיקה (test users) לא נתמכים, צריך חשבון מקצועי אמיתי.

4

ההתקנה

מריצים בטרמינל שלך. הסקריפט יוצר מסד נתונים, מפעיל מיגרציות, שומר את הסודות ב-Cloudflare ופורס. הוא שואל בהזנה מוסתרת את הטוקן ואת ה-app secret.

npm run setup -- --apply
  1. הסקריפט מציג את חשבון ה-Cloudflare. מקלידים yes אם זה הנכון.
  2. מקלידים את הטוקן ואת ה-app secret כשנשאל (לא רואים אותם בזמן ההקלדה, וזה תקין). הסקריפט בודק את הטוקן מול Meta, מוצא בעצמו את חשבון האינסטגרם, ורק אז יוצר משהו בענן.
  3. בסוף הוא גם מנסה לרשום את החשבון לאירועי תגובות והודעות. מוצגות כתובת הדשבורד וכתובת ה-webhook.
  4. הסיסמה וה-Verify token נשמרים בקובץ d-me-tokens.txt. פותחים אותו בעצמך, מעתיקים למנהל סיסמאות, ומוחקים אותו.
איך יודעים שהצליח: /health בכתובת שלך מחזיר {"ok":true}. הסקריפט בודק זאת בעצמו.

נתקע? Cloudflare לא מחובר: חוזרים לשלב 2. אין כתובת workers.dev: חוזרים לשלב 1. הפריסה נכשלה אחרי יצירת המסד: לא מריצים הכול מחדש, אלא בודקים בלוח (Storage & Databases, D1) ומריצים npm run deploy.

5

חיבור ה-webhook ב-Meta

ככה האינסטגרם שולחת ל-D-ME כל תגובה והודעה חדשה.

  1. באפליקציה ב-Meta: API setup with Unified login > Configure webhooks.
  2. Callback URL: כתובת ה-webhook משלב 4 (נגמרת ב-/webhook/instagram). Verify token: הערך מהקובץ d-me-tokens.txt. לוחצים Verify and save.
  3. מסמנים את השדות comments ו-messages.
  4. שני דברים שונים: ה-webhook של האפליקציה (עכשיו), ומנוי של החשבון לאירועים. את המנוי ההתקנה כבר ניסתה לעשות בעצמה. בלי מנוי של החשבון ה-webhook שקט.
איך יודעים שהצליח: Meta מאשרת את ה-Callback בלי שגיאה.
מגבלות מהתיעוד של Meta: האפליקציה חייבת להיות Live כדי לקבל התראות מגולשים. התראות על תגובות דורשות Advanced Access (App Review), ולייצור גם אימות עסק. החשבון חייב להיות ציבורי. ויש מגבלה זמנית: אם חשבון האינסטגרם לא מקושר לדף פייסבוק, התראות הודעות (כולל תגובות לסטורי וכפתור "עקבתי") עשויות לא להגיע. הפתרון של Meta: configuration נפרד שמבקש גם את הדף המקושר וההרשאה pages_show_list.

אם Meta לא מאשרת: ה-Verify token שונה ממה שנשמר, או שהכתובת לא נכונה. אם אחר כך אירועים מקבלים 401: ה-app secret שהוזן אינו זה ש-Meta חותמת איתו. מנסים את ה-App secret של האפליקציה (App settings, Basic) ומחליפים:

npx wrangler secret put IG_APP_SECRET --config wrangler.local.jsonc
6

הדשבורד והאוטומציה הראשונה

  1. פותחים את <הכתובת שלך>/admin. בשדה "מפתח ניהול" מזינים את הסיסמה מ-d-me-tokens.txt ולוחצים חיבור.
  2. בוחרים תוכן: פוסט, ריל או סטורי. אפשר לבחור כמה, או "כל הפוסטים".
  3. כותבים מילות תגובה (למשל "לינק"), את הלינק והודעה פרטית, ובוחרים אם לשלוח רק לעוקבים.
  4. שומרים. האוטומציה מופיעה ב"רצות עכשיו" בסיידבר, והקוביות מציגות את הספירות.
איך יודעים שהצליח: האוטומציה פעילה ברשימה, והפוסטים שלך נטענו.
7

בדיקת קבלה אמיתית

חשוב: לפי התיעוד של Meta, התראות על תגובות של גולשים מגיעות רק כשהאפליקציה במצב Live עם Advanced Access (App Review), ולייצור גם אימות עסק. כל עוד היא ב-Development אפשר לוודא את החיבור (אימות ה-webhook, התראת בדיקה מהלוח, /health, טעינת הפוסטים), אבל תגובה אמיתית של גולש עשויה לא להגיע. במקרה כזה השלב הבא הוא להגיש App Review.
  1. מהחשבון שלך, או מחשבון עם תפקיד באפליקציה (App roles), מגיבים על פוסט ציבורי במילת הטריגר.
  2. אם ההתראה מגיעה: ההודעה הפרטית מגיעה פעם אחת בלבד (הודעה אחת לכל תגובה, בתוך 7 ימים מהתגובה).
  3. אם הוגדרה בדיקת עוקב: מי שלא עוקב מקבל בקשה עם כפתור, ורק אחרי שעקב ולחץ מקבל את הלינק.
  4. אין התראה? בלוח של Cloudflare: Workers & Pages, ה-Worker, Observability. אם לא הגיעה בקשה, הסיבה כמעט תמיד אחת המגבלות בשלב 5.
ההקמה גמורה כשתגובה אמיתית הביאה הודעה פרטית. אם האפליקציה עוד לא Live, מה שנשאר הוא האישור של Meta.
8

תחזוקה

חידוש הטוקן, כל כ-50 יום

בודקים בלוח של Meta מה תוקף הטוקן. אם הוא פג אחרי כ-60 יום, מרעננים כשבועיים לפני ומוסיפים תזכורת ביומן (טוקן של משתמש מערכת לא פג). קריאה אחת מחזירה טוקן חדש:

https://graph.instagram.com/refresh_access_token?grant_type=ig_refresh_token&access_token=<הטוקן הנוכחי>

ואז שומרים אותו (מקלידים בהזנה מוסתרת):

npx wrangler secret put IG_ACCESS_TOKEN --config wrangler.local.jsonc

החלפת סיסמת הניהול

npx wrangler secret put ADMIN_TOKEN --config wrangler.local.jsonc
